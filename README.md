# iOS Configuration Profiles

`.mobileconfig` profiles for iOS/iPadOS, built from Apple's published payload schemas
rather than from memory, and documented with what each key actually binds — on an ordinary
unsupervised iPhone versus only under supervision.

Ground rules for anything added here:

- `PayloadVersion` is always `1` — it is the plist format version, not a revision counter.
  Revisions go in `PayloadDisplayName`.
- Keys are checked against [apple/device-management](https://github.com/apple/device-management)
  at build time, not recalled.
- Profiles are generated by a script with assertions, not hand-written XML.
- No key ships unless it binds. Supervised-only keys are labelled as such or left out.
- Every profile states what it *cannot* do before what it can.

## Profiles

| Directory | What it does |
|---|---|
| [`daita/`](daita/) | Research on Mullvad DAITA and why no profile can enforce it, plus the encrypted-DNS profile that covers the part of that threat model which *is* profile-enforceable. |
| [`tad/`](tad/) | DAITA's architecture rebuilt as an independent, profile-enforceable feature: a tested Maybenot integration, the iOS extension design, and a combined always-on VPN + DNSforge profile that really does pin the defense — because the app it targets reads it. |
| [`dvpn/`](dvpn/) | **DAITA VPN** — the data plane underneath that profile. Constant-size sealed datagrams, cover traffic and blocking on both ends, capability negotiation that fails closed, and a measurement harness. Runs as two processes over a real socket. |
